# GrantChina — CRM + Landing

Система для образовательного агентства GrantChina (Душанбе → обучение в Китае):

- **Лендинг** — публичный сайт с формой заявки и каталогом программ
- **CRM-панель** — рабочее место сотрудников: заявки, консультации, студенты,
  финансы, договоры, гранты, билеты, зарплата, диалоги, база знаний
- **Личный кабинет студента** — свои документы, статус заявки и график платежей
- **Backend API** — NestJS + PostgreSQL, realtime по Socket.io, фоновый
  планировщик, интеграции (Telegram, Brevo, SMS, IP-телефония, Claude API)

## Стек технологий

| Часть | Технологии |
|---|---|
| Backend | NestJS 10, Prisma 5, PostgreSQL, JWT (httpOnly cookie), Socket.io, Multer, `@nestjs/schedule`, `@nestjs/throttler`, Helmet |
| Интеграции | Telegraf (Telegram), Brevo HTTP API (email), Payom.tj / SMS.ru / Twilio (SMS), вебхуки IP-телефонии, `@anthropic-ai/sdk` (Claude) |
| Лендинг | React 18, TypeScript, Vite |
| CRM | React 18, TypeScript, Vite, React Router, Zustand, Axios, Framer Motion |

## Быстрый старт

### 1. PostgreSQL (через Docker)

```bash
docker compose up -d
```

PostgreSQL поднимется на `localhost:5432`, БД `grantchina`, пользователь
`grantchina`, пароль `grantchina`.

### 2. Backend

```bash
cd backend
cp .env.example .env             # отредактировать значения
npm install
npx prisma db push               # схема применяется push'ем, не миграциями
npm run seed                     # создать первого пользователя
npm run seed:knowledge           # 17 стартовых статей базы знаний
npm run start:dev
```

API стартует на `http://localhost:3001`.

> **Про миграции.** Проект намеренно живёт без `prisma migrate`: продовый
> деплой выполняет `prisma db push --accept-data-loss`. Отсюда правила схемы —
> новые колонки только nullable или с дефолтом, растущие справочники хранятся
> как `String`, а не `enum`.

### 3. Лендинг

```bash
cd frontend-landing
npm install
npm run dev
```

Откроется на `http://localhost:5173`.

### 4. CRM-панель

```bash
cd frontend-crm
npm install
npm run dev
```

Откроется на `http://localhost:5174`.

## Роли

| Роль | Что может |
|---|---|
| **FOUNDER** (Основатель) | Всё. Единственный, кто утверждает платежи, видит финансовую аналитику, правит формулы KPI, утверждает и выплачивает зарплату |
| **ADMIN** (Администратор) | Полный операционный доступ: все заявки и студенты, удаление записей, база знаний, ведомость зарплаты (без утверждения выплат) |
| **EMPLOYEE** (Менеджер) | Только свои записи: назначенные ему студенты и заявки плюс свободные (без ответственного). Своя зарплата и свои KPI |

Формула видимости одна на весь проект — `backend/src/common/access.ts`.
Чужая запись всегда отдаётся как **404, а не 403**: ответ не должен
подсказывать, что такая запись существует.

## Возможности

### Заявки и лиды
Вкладки «Все / Новые / В работе / Архив» со счётчиками, фильтры по источнику,
менеджеру, направлению и периоду, отметка повторных обращений, авто-архив
залежавшихся заявок (по умолчанию в безопасном режиме `dry`).

### Консультации
База консультаций с датой повторного звонка. Планировщик за сутки создаёт
менеджеру задачу-напоминание — забытый лид перестаёт быть вопросом дисциплины.

### Финансы
Шестиэтапный график платежей, «двойное подтверждение» (менеджер вносит —
Основатель утверждает), чек как обязательное доказательство оплаты, назначение
и способ платежа. Суммы хранятся в `Decimal(12,2)`.

### Договоры
Отдельная сущность с номером, суммой и сроками; график платежей привязан к
договору. На студента одновременно живёт только один активный договор —
это гарантирует уникальный индекс в БД, а не проверка в коде.

### Гранты
Реестр многолетних («двойных») грантов: год обучения, дата старта следующего
учебного года, перевод на следующий год. Планировщик за 1–2 месяца до нового
учебного года сам ставит менеджеру задачу.

### Билеты
Учёт перелётов: студент, город назначения, вылет и прилёт, номер рейса,
авиакомпания, статус, файл маршрутной квитанции. Фильтры по городу, статусу и
периоду («на эту неделю» / «на этот месяц» / свой период), экспорт в CSV.
Планировщик за 3 дня ставит менеджеру задачу, за сутки шлёт студенту SMS.

### KPI и зарплата
Оклад + бонусы по формулам, расчётный лист за период, утверждение и фиксация
выплаты руководством. У сотрудника — только свои показатели и свой лист.

### Диалоги
Единое окно переписки из мессенджеров (сейчас Telegram, каналы добавляются
одной строкой в `messaging/channels.ts`), привязка диалога к заявке или
студенту, назначение ответственного, счётчик непрочитанных.

### Звонки
Журнал звонков, click-to-call, всплывающая карточка клиента при входящем
вызове, приём вебхуков АТС. До подключения АТС разговоры фиксируются вручную —
таблица и интерфейс при подключении не меняются.

### База знаний и AI-помощник
Регламенты компании по разделам. Плавающий помощник отвечает сотрудникам
**строго по опубликованным статьям** этой базы: статьи подставляются в
системный промпт запроса (RAG), никакого дообучения модели нет. Черновики в
контекст не попадают. Без `ANTHROPIC_API_KEY` виджет не показывается.

### Журнал действий
16 типов событий с автором, ролью и деталями. Финансовые и кадровые действия
фиксируются всегда, даже если основная операция завершилась ошибкой уведомления.

## Уведомления

При создании заявки система:

1. сохраняет in-app уведомление сотрудникам (и шлёт его через Socket.io);
2. пишет в Telegram-чат (если заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`);
3. отправляет письмо администратору через Brevo (если задан `BREVO_API_KEY`).

Все каналы опциональны — незаданный просто пропускается. **Email идёт через
HTTP API Brevo, а не SMTP**: Railway блокирует исходящие порты 25/587.

## Фоновые задачи

| Задача | Частота | Что делает |
|---|---|---|
| `follow-up-reminder` | каждые 15 мин | задача менеджеру за сутки до повторного звонка |
| `application-auto-archive` | раз в сутки | архивирует (или в режиме `dry` только считает) залежавшиеся заявки |
| `academic-year-reminder` | раз в сутки | задача о продлении гранта за 1–2 месяца до нового учебного года |
| `flight-reminder` | раз в час | задача менеджеру за 3 дня до вылета, SMS студенту за сутки |
| `payroll-period-close` | раз в сутки | закрывает зарплатный период и формирует расчётные листы |

Планировщик целиком выключается переменной `SCHEDULER_ENABLED=0` (аварийный
откат). Каждая задача идемпотентна: повторный запуск на нескольких репликах не
создаёт дублей — механика описана в `scheduler/job.contract.ts`.

## Безопасность

- JWT в **httpOnly cookie** — токен недоступен из JavaScript
- Отдельный секрет и отдельная сессия для личного кабинета студента
- `/uploads` закрыт авторизацией: в нём лежат паспорта, справки, чеки и билеты
- Realtime-события несут **только идентификаторы**; имена и телефоны фронт
  запрашивает по HTTP, где права уже проверены
- Ничего не удаляется физически — везде soft-delete (`deletedAt`)
- Вебхуки (АТС, клиентский Telegram-бот) авторизуются общим секретом; пока
  секрет не задан, эндпоинт вебхука отвечает 401 на любой запрос

## Деплой

- **Backend** — Railway. `npm run start:prod` выполняет `prisma db push`,
  наполняет справочники и стартует приложение.
- **Фронтенды** — Vercel. CRM смонтирована на `/admin`; пути `/admin/api/*`,
  `/admin/uploads/*` и `/admin/socket.io/*` проксируются rewrite'ами на Railway,
  поэтому браузер всегда ходит на свой origin.
